**What it is.** SketchUp is a 3D modelling program from Trimble, aimed at architects, interior designers and builders. Its whole identity is the push/pull tool: draw a rectangle, push it into a wall. It's the fastest thing on the market for getting a room or a building shell blocked out, and it's easy enough that people learn it in an afternoon. It's not a general 3D package — no rigging, no character animation, no sculpting, no PBR authoring.

Tiers: **Free** (browser only), **Go** (~$140/yr, browser + iPad), **Pro** (~$400/yr, desktop), **Studio** (adds V-Ray).

**On your machine — this is the deciding fact.** There is no Linux build of SketchUp and never has been. Pro is Windows and macOS only. What you can run here is **SketchUp Free in a browser**, which is a genuinely reduced product: no extensions, and export limited to `.skp` and `.stl`. `.stl` has no UVs, no materials, no normals — it is useless as a pipeline into A-Frame. Every export format you'd actually want (OBJ, FBX, DAE, glTF) is behind Pro, which you can't install here.

**Can I drive it?** No. Pro has a Ruby API and can run scripts, but it's Windows/Mac and there's no headless mode worth the name; the web version has no automation surface at all. And `.skp` is a proprietary binary — reading it requires Trimble's SDK, so I can't even parse its output. It would be entirely manual work by you, with files I can only touch after you've exported them to something open.

Contrast that with **Blender**: free, native Linux, and fully scriptable in Python from the command line — which means I can actually do the work. There's already a script sitting in the other project, [tools/blend_to_glb.py](tools/blend_to_glb.py), written against a Blender that still isn't installed. `sudo snap install blender --classic` and that path opens up.

**For VR demos** there are three separate things people mean:

- **SketchUp Viewer** on Quest — walk your own model in VR. Requires a paid subscription, and it's a viewer: no interactivity you write, no mic, no audience logic. It shows a building. It cannot be your app.
- **Enscape / Twinmotion** — real-time architectural walkthroughs with VR output. Beautiful, and Windows-only.
- **Model in SketchUp → export glTF → load in A-Frame.** This is the only one that fits what you're building, and it needs Pro.

**Verdict for your two projects.** SketchUp's strength — architectural shells — is precisely the part you already solve better. Your room shells are A-Frame primitives with runtime-generated textures, and that's not laziness, it's the product: the walls have to change colour live. Geometry imported from SketchUp arrives baked, with auto-projected UVs, coplanar faces, no PBR, and materials you'd have to rebuild by name anyway. You'd trade your customisability for a nicer-looking mesh.

And for stage-studioVR specifically, the hall is the easy half. The audience is the hard half, and SketchUp cannot rig or animate a human at all.

**What I'd suggest instead:** install Blender. It covers what SketchUp would have done, runs here, and I can script it — cleanup, decimation, UV unwrapping, batch glTF export, even generating the seating layout procedurally. The one thing SketchUp has that Blender doesn't is **3D Warehouse**, a huge free model library strong on exactly your subject matter — auditorium seating, lecterns, furniture. That's worth browsing in a browser regardless of whether you ever model in it, though the models are user-uploaded, wildly variable in quality, and the licensing is loose enough that I'd check each one before it goes near a public deploy.

## The one that matters

```bash

pip install bpy                                          # Blender as a library
```

It does modelling, UV unwrapping, rigging, animation, retargeting, decimation, baking, and glTF export. Nothing else on this list covers that span. ## Code-CAD — you describe geometry, I write the description

Genuinely good for the *architectural* half of stage-studioVR: risers, seating rows, a raked floor. Useless for anything organic.

| | Language | Notes |
| --- | --- | --- |
| **OpenSCAD** | own declarative language | CSG, pure CLI rendering, deterministic output. Simple and reliable, but exports mesh only — no UVs, no materials, and parametric information is lost. |
| **CadQuery** | Python | Wraps OpenCASCADE, the same B-rep kernel under FreeCAD. Real fillets and chamfers, exact curved surfaces, exports STEP. |
| **build123d** | Python | Successor-in-spirit to CadQuery, same kernel; currently the best-supported code-CAD framework. |
| **FreeCAD** | Python | Full parametric CAD with a document object model, headless batch processing. Heavier than the above. |

## Pure libraries — no GUI exists at all

The most Claude-friendly category by definition, and the one that fits the *measure, don't guess* method from room-studioVR:

- **trimesh** — `pip install trimesh`. Load almost any format, measure bounding boxes, booleans, repair, convert. This is what I'd reach for to answer "which way does this model face" and "how big is it really".
- **PyMeshLab** — MeshLab's whole filter set from Python: decimation, remeshing, cleaning, UV parameterisation. Exactly the tool for turning a 40k-triangle 3D Warehouse chair into a 2k one.
- **Open3D** — point clouds, registration, reconstruction. More research-oriented.
- **assimp** — CLI format converter, reads ~40 formats.

## glTF pipeline CLIs — directly relevant to both your projects

These are one-line commands and they're the cheapest performance win available:

- **gltf-transform** (`npm i -g @gltf-transform/cli`) — inspect, dedupe, weld, simplify, resize textures, meshopt, Draco, KTX2. Composable, so you build exactly the pipeline you want.
- **gltfpack** (from meshoptimizer) — the blunt instrument: one command applies everything. `-cc` compressed output, `-tc` KTX2/BasisU textures, `-mi` mesh instancing. **`-mi` is worth remembering for the audience** — instancing is precisely the crowd problem.
- **gltf-pipeline** (Cesium) — Draco compression.
- **FBX2glTF** — you already use it.

## Engines

- **Godot 4** — free, MIT, Linux native, headless CLI export for CI, and you can run `.gd` scripts from the command line for batch asset work. Native OpenXR. Real caveat: shipping to Quest means an APK, which is the exact thing your no-USB-C constraint rules out. Its web export exists but is weak for XR.
- **Unity / Unreal** — free tiers, Unreal has Python scripting. Both are enormous installs, and neither escapes the sideloading problem.

## Characters — your actual hard problem

- **MakeHuman / MPFB2** — the modern form is a Blender add-on, which means it's reachable through `bpy`, which means I can script it. Parametric humans: height, build, age, all as numbers. That maps *very* well onto "generate forty different audience members".
- **Mixamo** — free auto-rigging and a large animation library. Web only, no API, manual downloads. Still probably the pragmatic source for the idle clips.
- **Blender + Rigify** — scriptable rigging if you want to own the whole chain.

## AI generation — real, but not on this machine

**Hunyuan3D 2.1** (Apache 2.0, PBR textures), **TRELLIS**, **TripoSR** (MIT, sub-second) all turn an image or prompt into a textured mesh and run locally under Python, so I could drive them. They want a CUDA GPU with ~6GB VRAM minimum. You have Intel integrated graphics from 2012, so these are cloud-or-nothing here. Also worth knowing: they output meshes, not rigs.

## Asset sources I can hit programmatically

```
https://api.polyhaven.com/types    →  ["hdris","textures","models"]
https://api.polyhaven.com/assets?type=hdris
```

Everything on it is **CC0**, which is the licence problem in room-studioVR solved outright. HDRIs, PBR textures and models, fetchable and filterable from a script. **ambientCG** offers the same shape of thing. That combination — a CC0 library with an API plus gltf-transform — is a fully automatable asset pipeline with no clicking anywhere in it.

**Install Blender, plus `trimesh` and `gltf-transform`.** That's the whole stack for both projects: Blender for anything creative, trimesh for measuring, gltf-transform for shipping. Add PyMeshLab when you start pulling in heavy downloaded models that need decimating.
